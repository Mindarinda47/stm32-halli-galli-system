# Original Material Review

## 결론

현재 보존 자료는 최종 팀 프로젝트의 결과를 설명하지만, 소스 코드는 전체 통합본이
아닙니다. 두 C 파일은 각각 독립 `main()`을 포함한 센서 실험이며, 현재 폴더만으로는
최종 시스템을 빌드할 수 없습니다.

## 확인된 자료 구성

- 설계·결과 문서 여러 버전
- 문서 내 하드웨어·동작 이미지
- 터치 센서 독립 코드
- 초음파 센서 독립 코드
- 결과 이미지 1개

문서 중 PDF와 DOCX 한 쌍은 내용이 거의 동일해 실질적으로 같은 결과물의 형식 차이로
판단합니다.

## 최종 보고서에서 추가 확인한 사실

- 최종 형태는 4인 플레이 구상에서 변경된 1인 대 컴퓨터 할리갈리
- 버튼, 터치센서, PIR 센서, LCD와 Bluetooth 스마트폰 터미널 통합
- 포트 한계와 안정성을 이유로 플레이 범위 조정
- PIR 센서의 물리적 위치와 판정 방식 변경
- 개인 역할로 코드 최적화, 인터페이스 설계, 디버깅, 테스팅, 하드웨어 설계 기록

터치 센서 코드는 최종 시스템의 입력 구성과 직접 연결됩니다. 초음파 센서 코드는 최종
보고서의 구성 요소에는 나타나지 않아, 프로젝트 과정에서 보존된 주변장치 실험 코드로만
분류합니다.

## 전체 소스로 볼 수 없는 근거

1. 두 C 파일이 각각 `main()`을 가짐
2. STM32 IDE project 설정이 없음
3. startup, linker, library 설정이 없음
4. 일부 외부 함수와 `printf` 지원 코드가 없음
5. 문서의 LCD, Bluetooth, 버튼, 게임 상태 로직이 소스에 없음
6. 통합 상태 machine과 시연용 main control flow가 없음

## 당시 완성 여부

당시 경험 회고와 최종 보고서를 종합해 다음 두 사실을 동시에 기록합니다.

- 당시 최종 팀 프로젝트는 완성 및 통과
- 현재 개인 보관 폴더에는 최종 통합 소스가 없음

## 기여도 판정

두 센서 코드는 대표 부분 코드로 포함했습니다. 최종 보고서의 역할 분담은 개인 기여
범주를 뒷받침하지만, 전체 통합 소스가 없어 특정 함수와 최종 변경 사항까지 연결할 수는
없습니다. 따라서 기능·역할 단위로 설명하고 코드 줄 단위 기여율은 주장하지 않습니다.

## 포트폴리오 판정

- 협업·통합 경험 사례: 활용 가능
- 전체 팀 코드 구현 사례: 현재 활용 불가
- 본인 대표 센서 모듈 사례: 부분 코드임을 명시해 활용 가능
- 2026년 독립 재구성: 원본과 구분하면 활용 가능
