# Collaboration

## 협업 사례로서의 가치

이 프로젝트의 핵심은 팀이 여러 하드웨어 모듈을 실제 시연 가능한 하나의 시스템으로
완성했다는 점입니다. 전체 소스가 없더라도 본인이 수행한 행동과 팀의 결과를 구분해
설명하면 협업 사례로 사용할 수 있습니다.

## 마감 전 통합 과정

프로젝트를 실행하고 검증할 수 있는 환경이 학교 실습실로 제한되어 있었고, 팀원 모두가
함께 작업할 수 있는 시간이 발표 전날에 집중되어 있었습니다. 저는 공동 작업일 외에도
실습실을 찾아가 코드를 분석하고 단독 테스트를 반복했습니다. 이를 통해 전체 게임 흐름과
각 기능의 연결 관계를 파악했고, 발표 전날 통합 작업에서 오류를 빠르게 좁힐 수 있었습니다.

통합 단계에서는 다음 작업을 맡거나 자발적으로 수행했습니다.

- 할리갈리의 카드와 점수를 LCD에 표현하는 화면·인터페이스 구성
- 게임 결과를 스마트폰 터미널로 출력하는 흐름 점검
- 부품을 브레드보드에 배치하고 연결하는 하드웨어 구성
- 전체 코드 구조 검토와 불필요하거나 중복되는 흐름 정리
- 점수 계산, 버튼 입력, 게임 진행의 반복 디버깅과 테스트
- 난이도, 게임 진행 순서와 규칙의 사용성 조정

테스트 중에는 점수가 잘못 계산되거나 버튼 입력 후 다음 단계로 진행되지 않는 문제,
입력에 반응하지 않는 문제가 나타났습니다. 정확한 저수준 원인은 현재 자료만으로 특정하지
않고, 당시 코드의 조건과 상태 값을 하나씩 바꾸며 주요 게임 진행 경로를 반복 실행한
사실만 기록합니다. 수정 후 카드 출력, 점수 계산, 버튼 입력과 결과 출력이 이어지는지를
확인했고 최종 발표 전에 전체 동작을 마쳤습니다.

## 팀에 기여한 행동

- 각자 담당 기능의 변경 사항과 진행 상태를 팀 단체 채팅방에 공유했습니다.
- 한 사람이 막힌 문제를 혼자 오래 붙잡지 않도록 함께 코드를 확인하고 해결 방향을
  논의했습니다.
- 시간이 부족한 상황에서는 기능 추가보다 최적화, 디버깅과 시연 안정화를 우선했습니다.
- 전체 구조와 게임 규칙을 파악한 뒤, 공식 담당으로 정해지지 않았던 통합 테스트와
  디버깅도 자발적으로 맡았습니다.
- 장시간 작업으로 팀이 지쳤을 때 남은 목표를 짧게 정리하고 끝까지 완성하자는 분위기를
  유지했습니다.
- 의견이 다를 때는 먼저 상대의 근거를 듣고, 더 적합한 제안은 수용하며 일부 관점을
  결합할 수 있는 타협점을 찾았습니다.

## 역할과 소유권 구분

| 구분 | 확인된 기여 |
|---|---|
| 직접 구현·설계 | LCD 카드·점수 인터페이스, 스마트폰 터미널 결과 출력 흐름 |
| 하드웨어 | 브레드보드 부품 배치와 연결 구성 |
| 통합 지원 | 전체 코드 구조 파악, 최적화, 디버깅, 반복 테스트 |
| 게임 완성도 | 난이도·진행 흐름·규칙 조정 |
| 팀 협업 | 진행 공유, 공동 문제해결, 의견 조율과 팀 사기 유지 |

전체 프로젝트 결과는 팀의 공동 성과이며, 위 항목만 개인 기여로 설명합니다.

## 공개용 협업 요약

> 실습실에서만 검증할 수 있고 팀의 공동 작업 시간이 제한된 상황에서, 개인 테스트로
> 전체 구조를 미리 파악하고 발표 전날 통합 작업에 참여했습니다. LCD 인터페이스와
> 결과 출력 흐름을 구성했으며, 공식 담당 범위를 넘어 점수·버튼·게임 진행 오류의
> 디버깅과 반복 테스트를 자발적으로 수행했습니다. 의견을 조율하고 팀이 마지막까지
> 작업을 이어갈 수 있도록 분위기를 유지해 최종 시연과 과제 통과에 기여했습니다.
